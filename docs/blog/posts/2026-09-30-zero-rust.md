# Kestrel compiles itself, and the Rust is gone

`v1.0.0-rc.1` is out, and it crosses a line the whole project was pointed at from
the start: **Kestrel is now written in Kestrel, and nothing else.** The compiler
that turns your `.kst` files into programs was itself built by a compiler written
in the same language — no Rust anywhere.

<!-- more -->

## How a language gets off the ground

Every new language faces the same chicken-and-egg problem. To compile Kestrel, you
need a Kestrel compiler. But to *write* the compiler in Kestrel, you'd need a
Kestrel compiler to compile it. Something has to come first.

So Kestrel started with a **seed**: a compiler for Kestrel, written in Rust. It
wasn't the goal — it was scaffolding. Its only job was to compile the *real*
compiler, the one written in Kestrel, until that one could stand on its own.

For the last stretch of betas, that's exactly what happened. The Kestrel-written
compiler learned to build everything the Rust seed could, then to reject the same
mistakes the same way, and lately to run some things *faster* than the seed did.
It quietly became the compiler you actually download.

## What just changed

With rc.1, the scaffolding comes down. The Rust seed — about **66,000 lines** — is
**deleted**. What's left builds itself:

- The compiler compiles its own source into a new compiler.
- That new compiler compiles the source again.
- The two outputs come out **byte-for-byte identical** — a fixed point. That's the
  proof it's stable: a compiler that reproduces itself exactly.

Think of it like a printing press that can print the complete plans for building
another press just like it — and the copy it prints is indistinguishable from the
original. Once you have one working press, you never need the workshop that built
the first one again.

To make that reproducible for anyone, each release ships a **seed of record**: one
trusted, prebuilt Kestrel binary. Point the build at it and it reconstructs the
whole compiler from source, start to finish, with no Rust toolchain on the machine
at all. We even run the build with `cargo` and `rustc` replaced by tripwires that
fail if anything tries to call them — and it sails through.

## What this means for you

Nothing in your code has to change. The language is the same, your programs compile
and run the same, and the binaries you download work the same way. This is a change
in how the compiler is *made*, not in what it does.

What it buys the project is honesty and independence: the tool that promises to
catch your mistakes is now held to its own promises. Every safety guarantee Kestrel
makes — memory safety, checked arithmetic, taint tracking — the compiler's own
source code lives under. It eats its own cooking.

## The road here, briefly

The betas were the climb: null safety, the trait system, diagnostics that match to
the letter, six shipped CPU architectures, checked-overflow and bounds elision that
claw back the speed, and last-use move elision. Every one of those had to work in
the Kestrel-written compiler before the Rust could go. rc.1 is where the ladder
gets kicked away.

## Get it

```bash
curl -fsSL https://raw.githubusercontent.com/kestrel-build/kestrel/main/install.sh | sh
```

A release candidate means we think this is what 1.0 looks like. If your programs
were correct, they still are — now built by a compiler that speaks its own language.
